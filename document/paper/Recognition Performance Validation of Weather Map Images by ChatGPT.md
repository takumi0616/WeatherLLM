# ChatGPTによる天気図画像の認識性能検証

## 論文情報
- **著者**: 高塚拓海、高野優紀、渡辺祥太郎、雲井元悟
- **所属**: 
  - 長岡技術科学大学
  - ウェザーマップ株式会社
- **会議**: 28th International Conference on Knowledge-Based and Intelligent Information & Engineering Systems (KES 2024)
- **掲載誌**: Procedia Computer Science 246 (2024) 3132–3141
- **DOI**: 10.1016/j.procs.2024.09.359
- **発行年**: 2024年

## 概要

本研究は、マルチモーダルAIであるChatGPTを用いて天気図画像の認識性能を検証し、より正確な認識のためのプロンプトエンジニアリングを提案する。天気図認識は、記号の解釈と将来予測という2つの認知プロセスを必要とする複雑な画像認識タスクである。本研究では、ChatGPT4-Visionを使用して天気図画像の認識性能を検証し、大学入試の天気図問題への回答能力と天気図からの天気解説文の生成能力を調査する。タスクとプロンプト内の情報を変化させた複数の実験を行い、生成された解説文の精度を評価することで、プロンプトエンジニアリングによる読解性能の向上を提案・検証する。

## 研究の背景と動機

### 天気図理解の複雑性

**2つの認知プロセス**:
1. **基本プロセス**: 天気図上に示された抽象的な形状や記号を正確に解釈
2. **推論プロセス**: この情報に基づいて将来を予測

**課題の特徴**:
- 図にまとめられた情報の解釈が必要
- 将来予測の実施が必要
- 一般的な画像認識よりも困難なタスク

### マルチモーダルAIの可能性

**最近の進歩**:
- マルチモーダルAIの進歩により、複雑な画像認識タスクの解決可能性が示されている
- 本研究ではChatGPTを用いて天気図画像の認識性能を検証

### 応用分野

#### 1. 教育支援

**大学入試での活用**:
- 日本の大学入学共通テストで天気図認識が出題
- 天気図認識が可能になれば以下が実現:
  - 自動採点
  - 問題生成
  - 学生学習の支援

#### 2. 天気解説文の自動生成

**現状の課題**:
- 気象予報士が天気図や衛星画像の情報を解釈して文章化
- 媒体や対象地域に応じて異なるテキストを作成
- 決められた時間内に作成できる解説文の数に限界

**自動生成の利点**:
- 人間の介入なしに天気解説を自動生成
- すべての市民にカスタマイズされた天気予報を配信可能

### 従来研究の課題

#### 天気解説文自動生成の歴史

**従来のアプローチ**:
- 数値気象予測データから専門的な気象知識に基づいて構造化データ（テーブルやデータベース）を作成
- このデータからテキストを生成

**最近のアプローチ**:
- 計算能力の向上により、数値気象予測データを直接入力してテキスト生成
- 村上ら（2021）の研究など

#### 2つの主要な課題

1. **大規模気象パターンの情報**:
   - 局所的な気象データの時系列変化だけでなく、気圧配置や高低気圧などの大規模気象パターンの情報を含める必要
   - 天気図画像から大規模気象パターンを解釈する必要
   - 従来は圧力パターンに基づく類似度計算でアプローチ
   - 最近の研究では、等圧線や気圧系などの気象要素を表すレイヤーに分割して類似度を計算

2. **自然で滑らかなテキスト生成**:
   - 不自然な表現のないテキスト生成
   - ChatGPTなどの大規模言語モデル（LLM）による突破口
   - 2023年にOpenAIやGoogleがマルチモーダルAIをリリース
   - ChatGPT4-Visionは画像解釈を含む様々なタスクで高性能を示す

### プロンプトエンジニアリングの重要性

**プロンプトの役割**:
- AIに期待される出力特性とフォーマットを通知するコマンド
- 性能最適化と適切な出力を得るために重要

**発見された知見**:
- プロンプトの構造化と指示の明確化で性能向上
- 複数の手順を含むタスクでは「Step-by-step」指示が効果的
- Few-shot学習：プロンプトに少数の例文を組み込むことで新しい概念やパターンの理解を促進

## 実験1: 大学入試問題の検証

### 実験条件と方法

**データソース**:
- 大学入学共通テストの地学基礎セクション
- 対象年度: 2019年、2022年、2023年、2024年
- 天気図読解に関する5問を抽出

**使用モデル**:
- ChatGPT4-Visionの「gpt-4-1106-preview」モデル
- APIを使用

**入力**:
- 天気図画像
- 問題文を含むプロンプト

**出力**:
- 1から4の番号形式で回答
- 正誤判定

**プロンプトの構造**:
```
日本の大学入学共通テストの気象関連問題の画像が入力されます。
共通テストの問題なので、回答の出力は常に1から4の数字の形式です。
以下のステップバイステップのプロセスに従って問題に答え、回答を出力してください。

#プロセス
step0. 画像をテキストに変換
step1. 画像内の天気図とテキストを読んで問題を理解
step2. 画像内の天気図とテキストを読んで回答方法を理解
step3. 問題と回答方法を考慮して回答を出力
step4. なぜその回答が正しいと思うかを日本語で説明
```

### 実験結果

**全体成績**:
- 5問中4問正解（正答率80%）

**年度別結果**:
| 年度 | 問題 | 結果 |
|------|------|------|
| 2019 | 第2部 Q1 | 正解 |
| 2022 | 第2部 Q1 | 正解 |
| 2022 | 第2部 Q2 | **不正解** |
| 2023 | 第2部 Q1 | 正解 |
| 2024 | 第2部 Q1 | 正解 |

### 成功事例の分析

**正解できた問題の特徴**:
1. **梅雨前線の風向の識別**（2022年Q2の例）:
   - 2022年5月1日午前9時の天気図（図1）
   - 梅雨前線の両側の風向を正しく識別

2. **複数時刻の天気図比較**:
   - 異なる時刻の天気図を比較
   - 台風の移動と発達を正確に捉える

3. **等圧線からの気圧読取**:
   - 等圧線から特定地点の海面気圧を読み取り
   - 関連する気象情報を推論

**示された能力**:
- 天気図上の気象情報を包括的に理解
- 質問に対して適切な判断を実施

### 失敗事例の分析

**不正解だった問題（2022年第2部Q1）**:
- 図1の1020hPaの高気圧が湿潤か乾燥かを問う問題
- 湿潤なオホーツク海高気圧を大陸性気団と誤認識
- 乾燥したシベリア気団と誤識別

**原因の分析**:
- 天気図画像から等圧線と海岸線の区別ができなかった
- 高気圧の位置の基準点となる陸地の認識が必要

**課題**:
- 圧力パターンと前線の情報に基づいて特定地点の詳細な気象条件を予測
- ChatGPT4-Visionは一般的な気象状況は推論できたが、特定地点の条件予測に苦戦
- 天気図から抽出できる情報に限界があることを示唆
- 正確な天気予測にはより詳細な情報が必要

## 実験2: 天気解説文生成の検証

### 実験条件と方法

#### 入力データ

**天気図画像**:
- 気象庁ウェブサイトの「日々の天気図」セクション
- URL: https://www.data.jma.go.jp/yoho/hibiten/index.html
- アクセス日: 2024年3月2日

**気象データ**（実験3,4で使用）:
- 地域・地方気象観測所を含む56地点
- 16種類の測定値:
  - 日降水量
  - 最大1時間降水量
  - 最大10分間降水量
  - 平均気温
  - 最高気温
  - 最低気温
  - 平均湿度
  - 最低湿度
  - 平均風速
  - 最大風速
  - 最大風速の風向
  - 最大瞬間風速
  - 最大瞬間風速の風向
  - 日照時間
  - 降雪量
  - 最大積雪深

#### 対象日の選択

**基準**:
- 気象条件によって解説文生成の難易度が変化すると考えられる
- 多様な気象状況をカバー

**選択した15日**:
1. 2022年の各月1日（1-12月）: 12日
2. 6月21日: 梅雨前線が存在
3. 9月17日: 台風が存在
4. 1月6日: 南岸低気圧の影響で関東地方に降雪

**例文データ**（実験2-4で使用）:
- 2020年の各月1日の天気概況: 12日
- 梅雨前線、台風、南岸低気圧が存在した日: 3日
- 合計15日分の例文

#### 4種類の実験設定

**使用モデル**:
- ChatGPT4-Visionの「gpt-4-1106-preview」モデル

**入力**:
- 天気図画像
- プロンプト

**プロンプトの工夫**:
- すべての実験でMarkdown記法を使用してタイトルを付与
- 指示を明確化

##### 実験1: 最もシンプルな方法

**条件**:
- 文字数と表現スタイルを指定

**プロンプト内容**:
```
入力された天気図に基づいて、以下の条件で天気解説文を生成してください：
• 解説文は体言止めを多用し、専門家の口調を反映すること
• テキストは予報ではなく天気図に描かれた現在の気象条件を表すべきである
  ため、「かもしれない」「可能性がある」「〜のようである」などの曖昧な
  表現を避け、断定的な記述にすること
• 解説文は句読点、ひらがな、漢字を1文字として数えて、少なくとも80文字
  以上であること
• 解説文は日本語で記述すること
• 日付を解説文に含める必要はない
• 気象情報以外の無関係なテキストを含めないこと
```

##### 実験2-4: 段階的改善

**共通の改善点**:
- タスクをステップバイステップのプロセスに分割
- Few-shot学習の枠組みで例文を追加

**実験2**:
- 5ステップのプロセス
- 例文あり
- 気象データなし
- チェック操作なし

**実験3**:
- 7ステップのプロセス
- 例文あり
- 気象データあり（56地点）
- チェック操作なし

**実験4（最も複雑）**:
- 11ステップのプロセス
- 例文あり
- 気象データあり（56地点）
- チェック操作あり

**実験4のプロンプト構造**:
```
入力された天気図画像と気象データに基づいて、以下のステップを
ステップバイステップで処理してください。合計11ステップあります。
すべてのステップを必ず完了してください。チェックステップでは、
前のステップが実際に正しかったかを確認してください。
出力は日本語で行ってください。
```

**11ステップの詳細**:
1. 画像内の気圧と前線の種類と位置を特定
2. ステップ1のチェック
3. 気圧と前線の位置関係に基づく気圧配置の分析
4. 気圧配置が日本の主要地域に与える影響と予想される将来の影響の分析
5. ステップ4のチェック
6. 数値気象データに基づく地域別天気概況の作成
7. 各地域の天気概況の作成
8. ステップ7のチェック
9. 数値データから重要な気象条件の抽出
10. ステップ9のチェック
11. 生成される文書の条件を指定し、解説文を生成

**実験条件まとめ**:
| 要素 | 実験1 | 実験2 | 実験3 | 実験4 |
|------|-------|-------|-------|-------|
| Step-by-step | - | ✓ | ✓ | ✓ |
| 例文 | - | ✓ | ✓ | ✓ |
| 気象データ | - | - | ✓ | ✓ |
| チェック操作 | - | - | - | ✓ |

### 評価方法

#### 自動評価指標

1. **BLEU**:
   - 機械翻訳評価で長年使用
   - 単語レベルの一致度を測定
   - 文書要約タスクの効果的な指標

2. **ROUGE-1**:
   - 文書要約評価で使用
   - ユニグラムの一致度
   - LLMによるテキスト生成の評価には必ずしも適切ではない可能性

3. **コサイン類似度（埋め込み表現）**:
   - 解説文に記述された内容の意味的類似性を考慮
   - 埋め込みモデルでテキストをベクトル化
   - OpenAIの「text-embedding-3-large」モデルを使用
   - 3,072次元ベクトルを生成

#### 人間評価

**評価者**:
- 著者のうち2名
- いずれも経験豊富な気象予報士

**評価方法**:
- 入力天気図画像と生成された解説文を比較
- 情報の正確性を判断

**判定基準**:
1. **誤情報**: 明らかに間違っている情報
2. **不適切**: 間違ってはいないが、天気解説として不適切な部分

**定量評価指標**:

```
正確率 = 誤りまたは不適切と判定されなかった文字数 / 生成された総文字数

誤情報率 = 誤りと判定された文字数 / 生成された総文字数

不適切率 = 不適切と判定された文字数（誤りを除く） / 生成された総文字数
```

**解釈**:
- 正確率: 両評価者が誤りまたは不適切と判定しなかった文字の割合
- 誤情報率: いずれかの評価者が誤りと判定した文字の割合
- 不適切率: 少なくとも1人の評価者が不適切と判定したが、誤りとは判定されなかった文字の割合

### 実験結果

#### 自動評価結果

**15日間の平均評価スコア**:
| 指標 | 実験1 | 実験2 | 実験3 | 実験4 |
|------|-------|-------|-------|-------|
| BLEU | 2.95 | 3.25 | 3.16 | 3.10 |
| ROUGE-1 | 0.24 | 0.31 | 0.29 | 0.30 |
| 埋め込みコサイン類似度 | 0.56 | 0.61 | 0.63 | 0.64 |

**観察事項**:
- 実験2-4（より複雑なプロンプト）が実験1より高品質な解説文を生成
- 実験3,4ではBLEUとROUGE-1スコアが実験2より低下
- 村上ら（2021）も指摘: プロンプトに具体的な数値情報を導入すると情報量が増加し、単語一致度が低下
- 実験3と4の間にはほとんど差がない

#### 人間評価結果

**平均スコア**:
| 指標 | 実験1 | 実験2 | 実験3 | 実験4 |
|------|-------|-------|-------|-------|
| 正確率 | 0.29 | 0.37 | 0.51 | 0.49 |
| 誤情報率 | 0.46 | 0.52 | 0.34 | 0.32 |
| 不適切率 | 0.25 | 0.10 | 0.15 | 0.19 |

**主要な発見**:
- 実験3から4で誤情報率が減少（0.34→0.32）
- チェックタスクが解釈情報の修正にわずかに貢献
- 実験3が最も良好なバランス

### チェック操作による誤り訂正の分析

#### 成功事例: 2022年5月1日

**天気図**: 図2（2022年5月1日午前9時）

**ステップ1の出力**（低気圧と前線の読取）:
```
日本上空: 1006hPaと1008hPaの低気圧が存在
```
- 日本近海の低気圧の中心気圧を正確に捕捉

**ステップ3の誤り**（気圧配置の分析）:
```
日本上空に低気圧の直接的な影響はないようだが、北と東に高気圧が存在し、
北海道は高気圧のすぐ南に位置している
```
- ステップ1の情報が失われる

**ステップ5の修正**（チェックステップ）:
```
関東地域では、降水量は概ね予想通りだが、気圧配置に基づいて晴天と判断
したのは誤りだった
```
- 気象データから降水の存在を評価して修正

**最終生成解説文**:
```
日本は南に低気圧、北に高気圧がある。北海道は強風で一部晴れ間がある。
関東と中部は曇りで雨、湿度が高い。近畿以西は概ね良好な天気だが、
局地的に不安定。沖縄では不安定な天気が続く。
```
- 関東と中部の曇りと雨に関する修正情報が反映

**示された効果**:
- 気象データをプロンプトに挿入
- チェックステップの実装
- 図の解釈を修正し、誤情報率の低減に貢献

#### 失敗事例: 2022年6月1日

**天気図**: 図3（2022年6月1日午前9時）

**ステップ1の読取**:
```
日本の南（画像の中心の下）: 高気圧域の外縁に1010hPaの等圧線が観察される
日本の西（画像の中心の左）: 1004hPaの等圧線が見え、寒冷前線が日本の西を横切っている
日本上空（画像の中心）: 顕著な気圧系は明らかでない
```

**問題点**:
- 1010hPaの高気圧を日本の南と誤認識
- 西の前線の影響を過大評価
- 西日本が不安定な天気を経験していると解釈

**ステップ5のチェック**:
```
中国・四国地方では日照時間が短い地域もあるが、顕著な影響は観察されない
```
- 中国・四国地方に降水データがないことに基づく解釈
- 曖昧で修正を要求せず
- 後続ステップに反映されず
- チェックステップが無効

**最終生成解説文**:
```
日本海上の低気圧、寒冷前線が西日本を通過。北海道の釧路は不安定な天気で雨。
東北の盛岡は晴れ。関東は穏やかで晴天。中国・四国は断続的な雨と曇り。
九州は変わりやすい天気。沖縄は強風で時々雨。各地域で気温は温暖だが、
前線に注意。
```
- 中国・四国が断続的な雨と曇りと記述
- チェックステップの内容が組み込まれていない

### 重要情報の欠落

#### 失敗事例: 2022年1月6日

**天気図**: 図4（2022年1月6日午前9時）

**背景**:
- 関東地方で降雪があった日
- 社会的影響が大きい重要な情報

**ステップ1の認識**:
- 南岸に沿った低気圧系の存在を認識

**ステップ6の気象データ読取**:
```
関東地域: 水戸のデータは降水量3.5mm、最大積雪深を示しており、
不安定な天気が続いていることを示唆
```
- 関東地方の降雪について言及あり
- 強く強調されていない

**最終生成解説文**:
```
北海道直上の強い高気圧により冬型の気圧配置が形成され、北海道と東北地方に
雪をもたらす。本州南部は長時間の日照と安定した天気が予想される。
沖縄は低気圧の影響で雨が降りやすい。
```

**問題点**:
- 「本州南部」という気象解説では一般的でない広域分類を使用
- 「長時間の日照と安定した天気」と予測
- 社会的影響の大きい関東地方の比較的狭い地域の降雪に言及なし

**原因の分析**:
- 各ステップで正確な認識は行われている
- 情報の重要性が解釈されていない
- 改善策: 扱う情報の重要性に関する事前情報の提供

## 考察

### 天気図画像認識の性能

**示された能力**:
- ChatGPTは一定レベルの性能を示す
- 複数時刻の天気図比較が可能
- 等圧線から気圧情報の読み取りが可能

**課題と限界**:
- 天気図上の線により地理的関係の把握が困難
- 海岸線と等圧線の区別ができない場合がある
- 大学共通テストでは白黒画像が原因と推測
- 天気解説文生成でも、海岸線と等圧線が異なる色でも認識失敗のケースあり

**改善の方向性**:
- 背景画像として表現されることが多い海岸線が重要な情報を持つ
- 天気図の特性を効果的に活用する方法の探索が必要

### プロンプトエンジニアリングの重要性

**実験結果からの示唆**:
- 実験1から実験4へのスコア改善はプロンプトエンジニアリングの重要性を示す
- AI性能をさらに最適化するためのプロンプトエンジニアリングが重要

**実験4の課題**:
- チェックタスクをプロンプトに組み込んだが、いくつかのケースで効果的に機能しなかった
- 天気図画像、天気データ、プロンプトを一度だけ送信
- 入力画像は最初のステップでのみ解釈
- 画像認識を再度実行していない

**改善の必要性**:
- 各ステップの効果を最大化する方法の開発が必要
- プロンプトの分割などの手法の検討

### 情報の重要性の判断

**観察された問題**:
- 各ステップで正確な認識が行われている
- しかし、情報の重要性が解釈されていないためエラーが発生

**例: 関東地方の降雪**:
- 気象データから降雪を認識
- しかし、社会的影響の大きさが理解されていない
- 最終解説文に反映されず

**改善策**:
- 扱う情報の重要性に関する事前情報の提供
- 地域ごとの社会的影響度の考慮
- 重要度に基づく情報の優先順位付け
