# Beyond Reference-Based Metrics: Analyzing Behaviors of Open LLMs on Data-to-Text Generation

## 論文情報

- **著者**: Zdeněk Kasner, Ondřej Dušek
- **所属**: Charles University, Faculty of Mathematics and Physics, Institute of Formal and Applied Linguistics
- **発表日**: 2024 年 1 月 18 日
- **arXiv**: 2401.10186v1 [cs.CL]

## 概要

本論文は、オープンソースの大規模言語モデル（LLM）が構造化データから一貫性のある適切なテキストを生成できる能力を調査した研究である。訓練データへのベンチマークリークによるバイアスを防ぐため、5 つのデータ・トゥ・テキスト（D2T）生成タスクからなる新しいアドホックベンチマーク「QUINTD-1」を構築した。

## 研究の背景と動機

### 既存の問題点

1. **データ汚染**: 既存の D2T ベンチマークが LLM の訓練データに含まれている可能性
2. **評価指標の限界**: 従来の参照ベース評価指標が人間の判断と相関が低い
3. **再現性の問題**: クローズド LLM（GPT-4 など）の使用による研究の非再現性
4. **評価の困難さ**: D2T 生成における長い入力、複雑な非線形構造、厳密な意味的正確性の要求

## QUINTD-1 ベンチマーク

### データ収集ツール「QUINTD」

5 つの異なるドメインから公開 API を使用してラベルなしの構造化データを収集するツール。

### 5 つのタスクとドメイン

| タスク ID   | ドメイン   | タスク説明                           | データソース      | フォーマット |
| ----------- | ---------- | ------------------------------------ | ----------------- | ------------ |
| openweather | 天気       | 天気データから天気予報を生成         | OpenWeather       | JSON         |
| gsmarena    | 技術       | 製品属性に基づく製品説明             | GSM Arena         | JSON         |
| ice_hockey  | スポーツ   | アイスホッケーの試合結果の説明       | Rapid API         | JSON         |
| owid        | 健康       | 時系列のキャプション生成             | Our World In Data | CSV          |
| wikidata    | 世界の事実 | 知識グラフのエンティティと関係の説明 | Wikidata          | Markdown     |

### データセット規模

- 開発セット: 500 例（各ドメイン 100 例）
- テストセット: 500 例（各ドメイン 100 例）
- データ収集期間: 2023 年 11 月〜2024 年 1 月

## 実験設定

### 評価対象モデル

**オープン LLM（7B パラメータ）**:

1. **Llama2-7B-32K-Instruct** (TogetherAI, 2023)
2. **Mistral-7B-Instruct-v0.1** (Jiang et al., 2023)
3. **Zephyr-7B-beta** (Tunstall et al., 2023)

**比較用クローズドモデル**:

- **GPT-3.5** (gpt-3.5-turbo-1106)

### プロンプト設計

```
Based on the given data:
```

{DATA}

```

Your task is to write a brief, fluent, and coherent single-paragraph
{output_type} in natural language. The text should be balanced and
neutral. Make sure that all the facts mentioned in the text can be
derived from the input data, do *not* add any extra information.

Start with "Sure! Here is the {output_type}: "
```

- 全ドメイン・全モデルで同一のプロンプトテンプレートを使用
- 決定的デコーディング（温度=0 相当）を採用
- 最大生成長: 512 トークン

### 予備実験からの重要な知見

1. **入力フィールドの選択**: 無関係なメタデータ（ID、タイムスタンプなど）を除外
2. **単位の明示**: 単位が曖昧な場合は明示的に追加
3. **長い入力の問題**:
   - 10-20k トークンを超える入力が存在
   - 32k コンテキストのモデルが必要
   - GPU メモリ消費が増大
   - Few-shot 学習が実現困難
4. **出力のプレフィックス**: "Sure! Here is the {output_type}: "" を追加してパース処理を簡素化
5. **流暢性 vs 正確性**: 出力は文法的・文体的に正しいが、事実エラーが多い

## 評価手法

### 参照フリー評価

入力データを基準として、人間の参照テキストなしで評価。

### 2 つの評価スキーム

#### 1. GPT-4 ベース評価（E_gpt）

- **モデル**: gpt-4-1106-preview
- **手法**: カスタムプロンプトでトークンレベルのエラーアノテーション
- **出力形式**: JSON 形式（理由、テキストスパン、エラータイプ）
- **特徴**: 各エラーに対して理由を生成させることで精度向上
- **コスト**: 約 45 ドル（全評価）

#### 2. 人間評価（E_hum）

- **プラットフォーム**: Prolific（クラウドソーシング）
- **アノテーター数**: 100 名
- **タスク量**: 各人 20 例（各ドメイン 4 モデル出力）
- **報酬**: 時給 £9（完了時間中央値: 47 分）
- **インターフェース**: TABGENIE ベースのカスタム Web インターフェース
- **可視化**: 各データ形式に対応したカスタム可視化

### エラー分類（4 カテゴリ）

| エラータイプ      | 説明                                         |
| ----------------- | -------------------------------------------- |
| **INCORRECT**     | テキスト内の事実がデータと矛盾               |
| **NOT_CHECKABLE** | テキスト内の事実がデータから検証不可能       |
| **MISLEADING**    | 文脈において誤解を招く記述                   |
| **OTHER**         | その他の問題（文法、文体、無関係、重複など） |

### 評価指標

1. **出力あたりの平均エラー数**（低いほど良い）
2. **少なくとも 1 つのエラーを含む出力の割合**（低いほど良い）
3. **エラーとしてマークされたトークンの割合**

## 主要な実験結果

### 全体的な正確性

#### オープン LLM（7B）の結果

- **E_hum 評価**: 74-85%の出力にエラーが含まれる
- **E_gpt 評価**: 88-93%の出力にエラーが含まれる
- **出力あたりの平均エラー数**: 2.5-3.8 個（E_hum）、3.4-3.8 個（E_gpt）

#### エラータイプ別の分布

- **INCORRECT**が最も一般的（出力あたり平均 2 回以上）
- **NOT_CHECKABLE**も頻繁（出力あたり平均 1 回以上、26%以上の出力に存在）

#### モデル間の比較

**オープン LLM（7B）**:

1. **Zephyr** - 最良性能
   - E_hum: 2.56 エラー/出力、74%の出力にエラー
   - E_gpt: 3.35 エラー/出力、88%の出力にエラー
2. **Llama2** - 2 番目
   - E_hum: 3.05 エラー/出力、85%の出力にエラー
   - E_gpt: 3.70 エラー/出力、92%の出力にエラー
3. **Mistral** - 出力が長く、エラーも多い
   - E_hum: 3.76 エラー/出力、80%の出力にエラー
   - E_gpt: 3.80 エラー/出力、93%の出力にエラー

**GPT-3.5**:

- E_hum: 1.38 エラー/出力、60%の出力にエラー
- E_gpt: 2.32 エラー/出力、75%の出力にエラー
- オープン LLM より優れているが、依然として高いエラー率

### ドメイン別の詳細結果

#### openweather（天気予報）

- **最も複雑**: 平均出力長 164 トークン
- **エラー率**: 90%以上の出力にエラー
- **平均エラー数**: 出力あたり 6-10 個

#### gsmarena（製品説明）

- **平均出力長**: 90-146 トークン
- **INCORRECT エラーが主**: モデルによって 0.34-1.95 個/出力

#### ice_hockey（スポーツレポート）

- **平均出力長**: 63-92 トークン
- **比較的バランスの取れたエラー分布**

#### owid（チャートキャプション）

- **平均出力長**: 60-91 トークン
- **INCORRECT エラーが多い**: 1.25-2.39 個/出力

#### wikidata（エンティティ説明）

- **最も単純**: 平均出力長 35-51 トークン
- **NOT_CHECKABLE エラーが主流**: 1.54 個/出力（E_hum）
- **INCORRECT エラーは少ない**: 0.12 個/出力（E_hum）
- シンプルな入力では外的幻覚（extrinsic hallucination）が発生しやすい

### 評価手法の一致度

#### 相関係数（Pearson）

- **ドメインレベル** (r_domain): 0.92 - 高い相関
  - モデルの高レベルランキングで良好な一致
- **例レベル** (r_example): 0.52 - 中程度の相関
  - 個別例の評価では一致度が低下
- **トークンレベル** (r_token): 0.25 - 低い相関
  - 具体的なエラースパンの解釈に差異

#### トークンレベルのエラーマーキング

- **E_gpt**: 20.4%のトークンをエラーとしてマーク
- **E_hum**: 21.4%のトークンをエラーとしてマーク
- **両者の一致**: 5.9%のみ
- エラースパンとカテゴリは解釈に依存するが、全体的な正確性評価では一致

## 推奨事項と今後の方向性

### 1. 正確性の改善に注力

- **現状**: 流暢性・文体は十分だが、意味的正確性が不足
- **必要**: 意味的正確性向上のための手法開発
- **方向性**: 新しいモデルベース評価指標の開発

### 2. 効率的なモデルの使用

- **課題**: 長いコンテキストによるメモリ問題
- **解決策**:
  - Flash Attention 搭載の効率的な長コンテキストモデル
  - 高速推論ライブラリ（exllama、llama.cpp）
  - 長コンテキスト Llama2 などの採用

### 3. 実世界でのテスト

- **生態学的妥当性**:
  - 実世界データでの継続的評価
  - 人間ユーザーによる評価
  - システムの実世界への影響評価

### 4. 多言語対応の機会

- **可能性**: オープン LLM による多言語 D2T 生成
- **低リソース言語**: D2T 生成の拡張
- **先行研究**: Lorandi and Belz (2023)など

### 5. 微細なバグへの注意

- **問題**: API コールの微妙なバグ（不正確な命令テンプレート、意図しない入力切り捨て）
- **リスク**: LLM の見かけ上の堅牢性により、バグが見過ごされモデル性能が歪められる可能性

## 技術的詳細

### 実験環境

- **GPU**: NVIDIA A40 (48GB VRAM)
- **精度**: 16 ビット
- **フレームワーク**: HuggingFace Transformers
- **API アクセス**: text-generation-webui（ローカル）

### データ収集の詳細

#### OpenWeather

- **API**: forecast5 API（5 日予報、3 時間解像度）
- **無料枠**: 1 日 1000 回の API コール
- **サンプリング**: 人口 1000 以上の都市からランダムに 100 都市選択
- **制約**: 無料 API ではリクエスト時点のデータのみ取得可能

#### GSMArena

- **ツール**: 非公式 gsmarena-api
- **制限**: IP アドレスごとのリクエスト数制限
- **サンプリング**: 各ブランドから 10 製品、合計 200 製品からランダム選択

#### RapidAPI Ice Hockey

- **人気度**: 9.1/10
- **制限**: 1 日 50 リクエスト
- **効率**: 1 リクエストで 1 日の全試合を取得可能
- **データ**: 2023 年 11 月 27 日と 29 日の試合データ

#### OurWorldInData

- **パッケージ**: owid-catalog（Python）
- **フォーカス**: 健康ドメインの時系列データ
- **データセット**: COVID データ、平均寿命データ
- **前処理**: タイトル、説明、単位を CSV コメントとして追加

#### Wikidata

- **ライブラリ**: wikidatasets
- **ドメイン**: 企業、国、映画、人物
- **プロパティ数**: エンティティごとに 2-10 個をランダム抽出
- **フォーマット**: Markdown リスト形式

### D2T 生成タスク

- **天気予報**: Sumtime-meteo、WeatherGov（Belz 2005, 2008; Liang et al. 2009）
- **製品説明**: ノート PC と TV（Wen et al. 2015, 2016）
- **スポーツレポート**: Rotowire ファミリー、SportSett:Basketball（Wiseman et al. 2017）
- **チャートキャプション**: 大規模データセット（Obeid and Hoque 2020; Kantharaj et al. 2022）
- **エンティティ説明**: WebNLG、知識グラフ（Gardent et al. 2017）

### LLM による D2T 生成

- **GPT-3.5 の評価**: WebNLG、AGENDA（Axelsson and Skantze 2023; Yuan and Färber 2023）
- **GPT-4 の忠実性**: テーブル・トゥ・テキストで最先端モデルを上回る（Zhao et al. 2023）

### 参照フリー評価

- **LLM ベース評価**: 人間判断との高い相関（Liu et al. 2023; Kocmi and Federmann 2023）
- **懸念事項**: 非再現性、バイアス
- **トークンレベルアノテーション**: 複雑な D2T 出力の評価プロトコル（Thomson and Reiter 2020）

## 研究の限界

### 1. 他の D2T 手法との比較欠如

- **理由**: 参照フリーベンチマークであり、既存手法は参照出力での訓練を前提
- **正当性**: オープン LLM の動作分析という主目的は達成

### 2. 参照フリー評価の課題

- **問題点**:
  - クローズドモデルへの依存
  - 特定のアノテーションプロトコル
  - 限定的な再現性
  - 高い実行コスト
  - 中程度の相互相関
- **展望**: オープンモデルベース指標による改善への期待

### 3. モデル選択の制約

- **制限**: 計算リソースの制約により 7B パラメータモデルのみ
- **訓練データの不透明性**: GPT-Neo、BLOOM と異なり、使用モデルは訓練データを非公開
- **重要性**: 訓練データに含まれない可能性のあるベンチマークでのテスト

### 4. 安全性への配慮

- **リスク**: LLM は事実的に不正確な情報を生成する可能性
- **必要性**: 生成テキストの慎重な検証
- **警告**: 生成テキストのみに基づく意思決定の禁止

## 結論

本研究は、オープン LLM による D2T 生成の探索的研究として、以下の新しい方向性を提案した：

### 主要な貢献

1. **QUINTD/QUINTD-1**: アドホックテストセットのための再利用可能なデータ収集ツールとベンチマーク
2. **参照フリー評価**: 標準フォーマットのデータを使用した参照不要の評価手法
3. **トークンレベル分析**: GPT-4 ベースと人間評価の組み合わせによる詳細なエラー分析
4. **実践的知見**: 5 つのドメインにわたるモデル動作の体系的分析と今後の方向性

### 主要な発見

1. **流暢性は達成**: 7B オープン LLM はゼロショット設定で様々な標準データ形式から流暢で一貫したテキストを生成可能
2. **正確性が課題**: 意味的正確性が主要な障害（80-91%の出力にエラー）
3. **長い入力の問題**: 長コンテキストモデル、GPU メモリ、Few-shot 手法の実現可能性に課題
4. **実践的ガイドライン**: 前処理（単位指定、不要フィールド削除、出力プレフィックス）による出力品質向上

### 研究資源

- **コード、データ、モデル出力**: https://d2t-llm.github.io で公開
- **再現性**: QUINTD ツールによる新しいデータセットの簡単な作成が可能

### 今後の展望

D2T 生成における正確性向上、効率的なモデルの開発、多言語対応、実世界での評価が今後の重要な研究方向である。本研究は、オープン LLM による D2T 生成の現状と課題を明らかにし、この分野の発展に貢献する基盤を提供した。
