# Harnessing Large Language Models for Disaster Management: A Survey

## 論文情報

- **著者**: Zhenyu Lei, Yushun Dong, Weiyu Li, Rong Ding, Qi Wang, Jundong Li
- **所属**: University of Virginia, Florida State University, Northeastern University
- **投稿日**: 2025 年 1 月 12 日
- **arXiv**: 2501.06932v1 [cs.CL]

## 概要

本論文は、自然災害管理における大規模言語モデル（LLM）の応用に関する包括的なサーベイである。災害の 4 つのフェーズ（緩和、準備、対応、復旧）とアプリケーションシナリオに基づいて既存研究を分類する新しい分類法を提案し、公開データセットの収集、主要な課題と機会の特定を通じて、災害管理における先進的な LLM 開発の指針を提供する。

## 研究の背景

### 自然災害の深刻化

- **増加する頻度と深刻度**: 人命、インフラ、環境に前例のない脅威
- **具体的事例**:
  - 2010 年ハイチ地震: 20 万人以上の死者、広範なインフラ破壊
  - 2020 年オーストラリア森林火災: 少なくとも 33 人の死者、推定 10 億匹の動物が死亡
- **緊急の必要性**: 効果的な災害管理戦略の開発

### LLM の革命的能力

- **文脈理解**: 優れた文脈的理解能力
- **論理的生成**: 論理的な生成能力
- **複雑な問題解決**: テキストデータと様々なモダリティのデータによる複雑な問題解決
- **災害管理への適合性**:
  - 膨大な災害リアルタイムデータの分析
  - 被災コミュニティとの動的なコミュニケーション促進
  - 重要な意思決定のサポート

### 研究のギャップ

- 体系的なレビューの欠如
- ベストプラクティスの特定が困難
- 研究ギャップの発見が不十分
- 災害関連課題への効果的な LLM 展開の最適化が不足

## 本研究の貢献

1. **体系的な紹介**: 4 つの災害フェーズにわたる LLM の現在の探索を体系的に紹介
2. **新しい分類法**: アプリケーションシナリオ、タスク、モデルアーキテクチャを統合した分類法の提案
3. **リソース収集**: 公開データセットなどの主要リソースを収集
4. **課題と機会**: 現在の課題と今後の研究機会を強調

## 背景知識

### 災害管理の 4 つのフェーズ

1. **緩和（Mitigation）**

   - リスクと脆弱性の特定
   - 災害予防のための積極的措置の実施

2. **準備（Preparedness）**

   - 包括的な計画と公衆教育
   - 今後の災害への準備態勢の確保

3. **対応（Response）**

   - 災害中の即座のニーズの特定と対処
   - 救助とリソース配分を含む

4. **復旧（Recovery）**
   - 被災地域の再建
   - 物理的・社会的影響への対処
   - 平常への復帰の促進

### LLM アーキテクチャの 3 つのタイプ

1. **エンコーダーベース LLM（ELM）**

   - 例: BERT
   - 主な用途: 下流タスクのためのテキスト特徴抽出

2. **デコーダーベース LLM（DLM）**

   - 例: GPT
   - 主な用途: 与えられたテキストクエリからのテキスト生成

3. **マルチモーダル LLM（MLLM）**
   - アライメントまたは特徴融合による複数モダリティの統合
   - テキスト、画像、その他のデータを処理

### 災害管理における主要タスク

1. **分類（Classification）**: 災害検出など
2. **推定（Estimation）**: 深刻度推定など
3. **抽出（Extraction）**: 知識抽出など
4. **生成（Generation）**: レポート生成など

## LLM の災害管理への応用

### 調査論文の分布

- **対応フェーズ**: 72.4%（最も多い）
- **準備フェーズ**: 13.4%
- **復旧フェーズ**: 12.6%
- **緩和フェーズ**: 1.6%

### 1. 災害緩和（Mitigation）

#### 脆弱性評価

**脆弱性分類**:

- インフラ脆弱性の特定
- エンコーダーベース LLM による教師あり分類
- デコーダーベース LLM によるゼロショットプロンプト学習
- ソーシャルメディアデータからインフラ故障の懸念を検出

**回答生成**:

- デコーダーベース LLM の活用
- 社会脆弱性指数（SVI）の検索に基づくコミュニティ脆弱性関連の質問への回答支援

### 2. 災害準備（Preparedness）

#### 2.1 公衆意識の向上

**知識抽出**:

- **エンコーダーベース LLM**:
  - BERT をファインチューニングしてニュースやソーシャルメディアから災害関連知識を抽出
  - 広範な文献からの抽出
  - BERT-BiGRU-CRF: 名前付きエンティティと関係認識（NER）の論理的一貫性を向上
- **デコーダーベース LLM**:
  - ChatGLM2 をファインチューニングして文書から知識トリプレットを抽出
  - 災害知識グラフの構築

**回答生成**:

- 導出された知識をデコーダーベース LLM のプロンプトに組み込む
- 山火事や洪水リスク関連の質問への回答
- 個別化された緩和ガイダンスの提供
- RAG（Retrieval-Augmented Generation）の活用

#### 2.2 災害予測

**発生分類**:

- エンコーダーベース LLM の活用
- BERT、GRU、CNN を統合して大規模ソーシャルメディアテキストから災害を予測
- マルチモーダル LLM による複数データモダリティの統合:
  - 歴史的洪水データ + BERT 埋め込み + XGBoost
  - 統計データからの特徴 + KNN
  - 衛星画像特徴 + ResNet
- デコーダーベース LLM と RAG による災害知識ベースからの歴史的洪水データ検索

#### 2.3 災害警告

**警告生成**:

- デコーダーベース LLM の活用
- ストリーミングデータから導出されたルールベースのアラートから明確な警告メッセージを生成
- National Weather Service の API から災害アラートを検索し、詳細なリアルタイム情報を提供

**画像生成**:

- マルチモーダル LLM とディフュージョンベースの text-to-image 生成モデル
- 差し迫った災害の鮮明な視覚的表現を生成
- アラートの明確性を向上

#### 2.4 避難計画

**計画生成**:

- デコーダーベース LLM の優れた推論能力を活用
- 脱出計画の立案と避難提案の提供
- 差し迫った災害に対する公共の安全を向上

### 3. 災害対応（Response）

#### 3.1 災害識別

**関連性分類**:

- **エンコーダーベース LLM**:
  - 災害関連投稿のバイナリ分類
  - ファインチューニングによる広範な活用
  - CrisisTransformers: 数百万の危機関連ツイートで事前訓練
  - アクティブラーニングの組み込み（ラベル付きデータが限られた場合）
- **フレームワーク設計の革新**:
  - アンサンブルモデル: 様々な LLM の強みを統合
  - CNN + att-BiLSTM: 時間的依存性と局所パターンを捕捉
  - GNN: 単語関係グラフの構築
  - GNom: 多言語単語グラフと BERT テキスト埋め込みをクロスアテンションで統合
- **先進的デコーダーベース LLM**:
  - Llama-2、GPT-4 による分類プロンプティング
- **マルチモーダル LLM**:
  - テキスト + 画像の組み合わせ
  - BiLSTM モジュールの追加
  - アテンションメカニズムによるテキストと画像特徴の融合
  - CycleGAN + 混合融合戦略
  - 半教師あり最小最大エントロピードメイン適応フレームワーク

#### 3.2 災害状況評価

**状況分類**:

- エンコーダーベース LLM のファインチューニング
- RoBERTa + SVM によるバイナリ分類
- BERT によるツイートのフィルタリング + NER による位置抽出
- マルチモーダル LLM: BERT + CNN による画像を利用した災害深刻度分類

**深刻度推定**:

- デコーダーベース LLM: Chain-of-Thoughts（CoT）プロンプティング
- Gemini による地震強度の修正メルカリ震度（MMI）値の推定
- マルチモーダル LLM: GPT-4 による洪水画像と説明からの洪水深推定

**説明生成**:

- マルチモーダル LLM による状況画像からの説明生成
- GPT-4V による視覚情報のテキスト翻訳
- GPT-4 による災害画像データからの評価説明生成

#### 3.3 災害情報調整

**有用性推定**:

- エンコーダーベース LLM（BERT、RoBERTa）
- 有用性評価を計算して情報ツイートをフィルタリング

**関連性分類**:

- エンコーダーベース LLM のファインチューニング
- 複数の関連性レベルによる投稿分類

**情報分類**:

- エンコーダーベース LLM のファインチューニング
- 情報タイプ別の投稿分類:
  - 実行可能タイプ: 「マネージャーにとって重要」
  - 人道的タイプ: 「負傷者」
  - 災害タイプ
- **パフォーマンス向上のための先進的技術**:
  - データ拡張: ハッシュタグとエンティティによるツイート拡張
  - 自己訓練: BerTweet によるソフトラベリング
  - BERT-Bi-LSTM-CNN: 時間的依存性と局所パターンの捕捉
  - GAT: ツイート埋め込みと情報タイプ間の相関を捕捉
  - FF-BERT: BERT と CNN のアンサンブル
- **帰納バイアスの導入**:
  - BERTweet による根拠（分類支援証拠）の抽出
  - RACLC: 対照学習による根拠抽出の精緻化
- **先進的デコーダーベース LLM**:
  - 命令チューニング、ゼロショット、Few-shot プロンプティング
- **マルチモーダル LLM**:
  - BERT と視覚モデルの特徴を集約により結合
  - クロスアテンションメカニズム: DenseNet 画像特徴 + BERT テキスト埋め込み
  - デュアルトランスフォーマー: ALBERT テキスト特徴 + S-CBAM-VGG 画像特徴
  - "OR"セットによるテキストと画像分類結果の組み合わせ

**ニーズ分類**:

- エンコーダーベース LLM による災害ニーズの検出
- 救助要請の検出
- MulTMR: 複数の教師モデルによる BERT と RoBERTa のファインチューニング
- XLM-RoBERTa による埋め込みとコサイン類似度ベースの検索でニーズとリソースをマッチング

**位置抽出**:

- エンコーダーベース LLM のファインチューニング
- 位置参照認識（LRR）: トークンを「内部位置」（ILOC）、「その他のトークン」（O）に分類
- アテンションと Bi-LSTM レイヤーの追加
- BERT-BiLSTM-CRF: 抽出位置の論理的一貫性を向上
- 外部知識ベース: コサイン類似度による投稿エンティティとのマッチング
- デコーダーベース LLM:
  - Llama-3 による位置関連語の抽出プロンプト
  - GPT-4 による詳細な位置説明（geo-knowledge 組み込み）
  - GeoChatGPT: 地理データと OCR ベースのオブジェクト説明を拡張

**要約抽出**:

- エンコーダーベース LLM と整数線形計画法（ILP）
- 重要な投稿と根拠の特定
- BERT ベ埋め込みと word2vec キーフレーズ埋め込みによる顕著性スコア計算
- デコーダーベース LLM:
  - LSTM による重要ツイートのランク付け
  - T5 モデルによる上位取得ツイートからの要約生成

**レポート生成**:

- デコーダーベース LLM による構造化された災害報告
- ゼロショット検索ベース生成
- 複数の LLM の使用: 文書検索、再ランク付け、命令追従要約
- Chain-of-Thought（CoT）推論の活用
- Crisis2Sum: クエリ関連情報をトピッククラスターに整理し、Mixtral で要約

#### 3.4 災害救助

**計画生成**:

- デコーダーベース LLM のプロンプティング
- 実行可能な対応計画の生成
- 重要なガイダンスの提供

**コード生成**:

#### 3.5 災害問題相談

- よくある質問への回答とガイダンス提供

### 4. 災害復旧（Recovery）

#### 4.1 災害影響評価

**損傷分類**:

- エンコーダーベース LLM による災害損傷の特定と分類
- BERT による損傷関連投稿の特定と分類:
  - 「人的損害」または「インフラ損害」
  - 4 つのタイプ: 「水道または電力供給」など
- BERT-BiLSTM-Sit-CNN: テキスト理解の向上
- 損傷深刻度の測定

**損傷推定**:

- エンコーダーベース LLM による損傷深刻度スコアの計算
- 投稿トークンとシード語の埋め込み間の類似度に基づく

**回答生成**:

- デコーダーベース LLM: RAG を使用した特定の評価質問への回答
- マルチモーダル LLM:
  - GPT-4o による建物画像を使用した損傷評価生成
  - SAM-VQA: 教師ありアテンションベース VLM で画像と質問特徴を統合

**統計抽出**:

- デコーダーベース LLM による死傷者情報の抽出
- Few-shot 学習を通じたソーシャルメディアからの抽出

**感情分類**:

- エンコーダーベース LLM のファインチューニング

#### 4.2 復旧計画生成

**計画生成**:

- デコーダーベース LLM のプロンプティング
- 特定の復旧シナリオでの復旧・再建計画の生成
- ChatGPT による事業復旧のための災害復旧計画の構築

#### 4.3 復旧プロセス追跡

**感情分類**:

- エンコーダーベース LLM（BERTweet）
- 災害後の復旧期間を通じた公衆感情の評価
- 対応者が被災住民の感情的ニーズに対処するための復旧努力の調整を可能に

## データセット

### データセットの種類と特徴

#### 分類データセット

- **主な入力**: Twitter やニュースからのテキストデータ
- **カテゴリ**:
  - 情報性（関連性）
  - 人道的タイプ
  - 損傷レベル
  - その他の属性
- **視覚データ**: 衛星画像やソーシャルメディア画像を含むものもある
- **評価指標**: 精度、F1 スコア

#### 推定データセット

- **入力**: テキストと視覚データ
- **ラベル**: 洪水深などの定量的ラベル
- **評価指標**: 平均絶対誤差（MAE）など

#### 生成データセット

**2 つのカテゴリ**:

1. **質問応答**:
   - 災害関連の質問と回答のペア
   - マルチモーダル質問応答データセット（画像を含む）
2. **要約**:
   - 大量の文書入力
   - ドメイン専門家による参照要約

- **評価指標**: ROUGE、BLEU

#### 抽出データセット

- **タスク**: 文内の特定要素の識別とラベル付け
- **対象**: キーワード、位置
- **ラベル**: 「外部」、「開始」、「終了」
- **評価**: 分類指標

### 主要な公開データセット

#### 分類データセット（代表例）

1. **CrisisLexT6**: 2012-2013 年の 6 つの危機イベント、関連性分類
2. **CrisisLexT26**: 2012-2013 年の 26 イベント、関連性と 6 つの人道カテゴリ
3. **CrisisNLP**: 2013-2015 年の 19 の災害イベント、52,656 サンプル
4. **CrisisMMD**: 2017 年の 7 つの自然災害イベント、16,058 のツイートと画像のペア
5. **CrisisBench**: 9 つの既存データセットを統合した包括的ベンチマーク、109,796 サンプル
6. **HumAID**: 2016-2019 年の 19 の災害における 77,000 のラベル付きツイート
7. **Multi-Crisis**: 7 つのデータセット、53 の危機イベント、9 つのドメイン、164,625 サンプル

#### 推定データセット（代表例）

1. **Did You Feel It (DYFI)**: 地震後のオンラインアンケート、750,000 の回答
2. **FloodDepth**: 150 の洪水写真、洪水深推定用
3. **Behavioral Facilitation (BF)**: 2018 年北海道地震後のデータ、有用性評価付き

#### 抽出データセット（代表例）

1. **DisasterMM**: 洪水関連の Twitter データ、関連性分類と位置抽出用
2. **Re ́SoCIO**: Wikipedia と災害データセットの統合、9 つの NER ラベル
3. **CrisisNLP（抽出用）**: 根拠抽出用にアノテーション

#### 生成データセット（代表例）

1. **CrisisFACTS**: 8 つの危機イベント、748,466 サンプル、マルチプラットフォームデータ
2. **DisasterQA**: 7 つの情報源からの災害関連多肢選択問題、707 サンプル
3. **FFD-IQA**: 2,058 画像と 22,422 の質問-真実値ペア
4. **FloodNet**: ハリケーンハービー後の 4,500 の質問-画像ペア

## 課題と機会

### 1. データセットの不足

- **現状**: 分類タスクに偏重、他の重要分野が十分に代表されていない
- **課題**: 高品質データセット作成には多大な労力とリソースが必要
- **解決策**: 合成データ生成などの革新的ソリューション
- **機会**: 災害関連シナリオ全体でのカバレッジ拡大

### 2. 効率的な展開

- **課題**:
  - 大規模 LLM の遅延と計算上の課題
  - 緊急災害シナリオでのリアルタイム意思決定を妨げる
- **軽量モデルの利点と欠点**:
  - 利点: より高速でリソース効率的
  - 欠点: 精度と堅牢性を犠牲にすることが多い
- **必要性**: 効率性と信頼性のバランスを取るモデルの進歩

### 3. 堅牢な生成

- **幻覚のリスク**:
  - 出力が事実的に不正確な可能性
  - 災害コンテキストにおける深刻なリスク:
    - 誤った避難ルート
    - リソースの誤配分
    - 生命の潜在的損失
- **解決策**:
  - 外部知識ベースとの RAG 統合
  - 広範なドメイン固有の訓練
  - 不確実性推定
- **機会**: 幻覚出力への対処メカニズムの開発

### 4. 応用の不均衡

- **現状**: 対応フェーズに過度に集中（72.4%）
- **必要性**: 全災害フェーズでの使用拡大
- **ギャップ**: 新しいアーキテクチャに焦点を当てる研究者と、災害固有のソリューションを必要とする実務者の間のギャップ
- **機会**: 様々な課題に合わせた LLM の開発

### 5. 学際的協力の必要性

- **現状**: NLP と災害管理コミュニティ間のギャップ
- **出版統計**:
  - 既存 LLM の活用と新フレームワーク開発の分布に偏り
  - NLP や AI 専門の会議/ジャーナルへの発表が相対的に少ない
- **必要性**:
  - LLM 研究コミュニティのこの領域への関与の限定
  - 分野内での認識と焦点の高まりが必要

## 研究の限界

### 1. スコープの制約

- 既存 LLM が活用されている災害管理アプリケーションのみに焦点
- 現在の LLM 研究で探索されていない潜在的シナリオは除外
- 未探索領域は将来の進歩に有望だが、スペース制約のため範囲外

### 2. データセットの包含基準

- 既存研究で使用されたデータセットのサブセットのみ含む
- 容易にアクセス可能なデータセットを優先
- 多くのデータセットは:
  - オープンソース化されていない
  - 制限的なアクセスポリシー
  - 保証された品質が欠如
  - 再現性とさらなる研究に適していない

## 統計と洞察

### 出版傾向

#### LLM 活用と新フレームワーク開発

- **既存 LLM の活用**: 大多数
- **新フレームワークの開発**: 相対的に少数
- **示唆**: アプリケーション重視、ファインチューニングやプロンプティングによる既存 LLM の活用が主流

#### フェーズ別の研究量

- **対応（Response）**: 圧倒的に多い
- **他のフェーズ**: 限定的な探索
- **示唆**: 災害管理シナリオ全体での研究拡大の必要性

#### 学術発表の分布

- **AI/NLP 専門の会議・ジャーナル**: 相対的に少ない災害管理論文
- **その他の分野**: より多くの発表
- **示唆**: LLM 研究コミュニティからの限定的な関与
